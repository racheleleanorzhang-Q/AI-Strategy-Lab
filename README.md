# 🧠 AI Strategy Lab

**基于世界模型的通用策略模拟台**。用于在真实决策发生前，把策略放入可解释的数字世界中进行推演、比较与复盘。

> 产品名称与平台定位保持通用；具体业务以可扩展的策略场景接入，而不是将平台绑定到单一领域。

## 策略场景

### 1. AI 产品策略（原有场景）

保留原有首页 `StrategySimulator` 的完整能力：

- AI 产品定价、免费额度与模型成本策略
- 用户使用、留存、收入、成本与利润模拟
- 多策略和多模型对比

### 2. 产品组合经营策略（新增场景）

路由：`/portfolio-strategy`

以 **家庭 One ID × 用户旅程阶段 × 当前车库 × 候选车型** 为基础粒度，展示：

- 家庭 One ID、成员角色、家庭车库与购车机会
- 从需求产生到增换购周期的用户旅程
- 我方产品组合、竞品、延迟购买、保留现车与不购买之间的关系
- 6 类可交互浏览的家庭数字样本

Phase 1（迭代 0 + 1）保留业务世界表达与 6 类家庭数字样本浏览；Phase 2 新增“新车型上市后的产品组合经营”主链路：

1. 定义经营问题；
2. 分别配置基准与实验策略（上市开关/定位、价格、权益、目标家庭、销售动作、交付周期）；
3. 运行前端确定性 Mock 仿真；
4. 预览组合销量、利润、真正新增、内部蚕食、竞品抢夺、延迟释放与家庭覆盖；
5. 下钻 6 类家庭，核对策略前后选择、代表权重与规则解释。

Phase 3 在上述主链路后补齐可核算的组合经营决策层：

- 组合经营结果驾驶舱：组合销量、收入、利润、家庭覆盖、权益成本与投入产出；
- 车型级销量 / 收入 / 利润结构，以及首购 / 增购 / 换购结构；
- 家庭级迁移流向，明确真正新增、竞品抢夺、延迟释放、内部蚕食、保持和流失；
- 家庭下钻增强为“车型 + 原因 + 销量 / 利润 / 覆盖贡献”；
- 按“发生了什么 / 为什么 / 谁受影响 / 风险 / 建议”动态生成结构化解释；
- 显示规则置信度、敏感性风险与 Mock 边界，避免暗示真实市场预测。

所有聚合指标均可由 `families` 和 `migrationFlows` 中的代表家庭权重逐项核算；车型结构和购车类型结构之和与组合销量一致。驾驶舱拆分为 `PortfolioDashboard`、`MigrationAnalysis` 和 `AIInsight`，不引入新的可视化依赖。

Phase 4 新增多方案策略优化工作台：

- 同时勾选 2–4 套策略，内置增长优先、利润优先、平衡经营、用户覆盖四套高质量 Mock 预设；
- 支持销量优先、利润优先、用户覆盖优先、平衡经营四种目标偏好；
- 对销量、利润、家庭覆盖、内部蚕食、竞品抢夺、权益成本和置信度做候选集内 Min–Max 归一化，按目标权重计算相对综合分，并逐项展示贡献；
- 对价格、权益、交付周期、销售动作和产品定位执行单变量 ± 扰动，展示销量、利润、综合分变化及关键变量排名；
- 动态推荐当前目标下的较优方案，说明主要贡献、目标权衡、关键变量和风险，但保留人工最终选择；
- Phase 4 逻辑拆分在 `lib/portfolio-optimization`，界面拆分为 `StrategyOptimizationLab`、`ScoreBreakdown` 和 `SensitivityPanel`。

综合分仅用于当前候选方案的相对排序，候选集变化会导致归一化结果变化；它不是预测值、成交概率或自动决策依据。敏感性分析也只是固定规则下的局部情景扰动，不是统计置信区间。

Phase 5 新增“实验—回流—校准”闭环：

- 从 Phase 4 四套预设策略一键生成结构化实验草案，明确假设、家庭筛选、实验/对照分组、虚构区域门店、周期、样本量、变量和角色；
- 同时追踪增量试驾率、增量下订率、组合销量、内部蚕食、增量利润，以及投诉率、家庭触达频次、权益成本、门店负载四类护栏；
- 提供 Mock 状态推进、仿真预期与实际结果对照、动态偏差计算和透明规则归因；
- 根据回流生成世界模型参数/规则校准候选，展示校准前后、版本变化和人工双确认动作；
- 显式呈现“经营问题 → 仿真 → 方案比较 → 实验 → 回流 → 校准”链路，并设置效果、成本、负面事件与伦理停止条件。

Phase 5 的类型、合成数据和解释逻辑位于 `lib/experiment-loop`，界面位于 `components/portfolio/experiment-loop`。所有实验对象、门店、事件、结果和模型版本均为 **Mock / 合成数据**；不连接 CRM 或业务系统，不执行真实分流、触达、定价、下发或生产模型更新。

Mock 引擎位于 `lib/portfolio-simulation`，采用“定位匹配 + 目标圈选 + 净成交价 + 销售动作 + 交付周期”的透明固定规则，无随机数、无后端调用，同参数始终得到同结果。当前仍是产品设计 Demo，不代表生产预测。页面中的城市、家庭、品牌、车型和数值均为 **Mock / 合成数据**，不包含公司内部数据。

## 本地运行

```bash
npm install
npm run dev
```

质量检查：

```bash
npm run lint
npm run build
```

项目使用 Next.js 静态导出，并配置 GitHub Pages `basePath`。站内导航使用 Next.js `Link`，兼容 Pages 子路径部署。

## GitHub Pages 发布保护

`.github/workflows/deploy.yml` 仅保留 `workflow_dispatch` 手动触发：

- 合并或推送到 `main` **不会**自动部署；
- 不会因合并自动覆盖 `gh-pages`；
- 仅在维护者明确触发 Deploy workflow 时才构建并发布 `out` 到 `gh-pages`。

请不要直接修改 `gh-pages` 分支；需要发布时在 GitHub Actions 中人工确认后执行。

## 核心理念

> 不要在真实用户身上试错，先在“虚拟世界”里跑一遍策略。
